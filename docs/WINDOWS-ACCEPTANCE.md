# Windows acceptance plan (manual, do not treat headless Actions success as a pass)

Conduct on a spare Windows 10/11 x64 user account and a safe, disposable test profile. Do not run destructive tests against personal installed-app data. Capture time-stamped observations. Always test by launching `QBZDownloaderPortable.exe` at root, not the unpacked upstream Electron binary.

1. **Package provenance:** verify ZIP and PAF SHA-256 from `SHA256SUMS.txt` in the builder release; read `Other/Source/build-identity.json`, verify source commit/version; verify `.exe` files are real Windows PE x64 executables. Compare release tag and package revision.
2. **First run:** extract the ZIP to a path containing spaces and Unicode, e.g. `D:\Portable Tests\Música QBZ\QBZDownloaderPortable`; launch the root EXE. Confirm dashboard, searches and local backend start without manual installs. Check `Data/Electron/`, `Data/Backend/data/qbz.db`, `Data/Logs/`, and `Data/Downloads/` exist. Do not supply real account credentials on shared machines.
3. **Persistence:** change theme, preferences and download settings; add an authorized track download, exit fully, reopen; confirm settings/history/queue and database survive. Verify `Data/Backend/data/.secret.key` and SQLite WAL/SHM state stay with Data.
4. **Media helpers:** verify a legal authorized track converts with bundled ffmpeg and quality analysis/fingerprinting uses bundled fpcalc. Verify no unexpected dependency install or PATH requirement.
5. **Comprehensive process-tree observation:** use Task Manager/Process Explorer and ProcMon with application PID and descendants. Snapshot application-owned `%APPDATA%`, `%LOCALAPPDATA%`, `%USERPROFILE%`, `%PROGRAMDATA%`, `%TEMP%`, HKCU/Run, file associations, and user Start Menu before/after. Also look for empty directories. **Do not delete any unexplained paths.** Attribute writes to Electron, backend, Windows, installer, or dependencies.
6. **Installed coexistence:** separately set up installed QBZ on a throwaway user, populate distinct settings, then run portable. Check no installed settings are overwritten, no installed Start Menu links/COM registrations are touched, and the distinct `com.ifauze.qbzdownloader.portable` AUMID does not hijack installed notifications.
7. **Window + notification functionality:** test multiple UI windows if applicable, taskbar progress, notification delivery, toast click-to-open and activation after Explorer restart. Windows 10/11 notification support depends on Windows shell registration. Log a failure if toasts fail, rather than claiming portability proved.
8. **Lifecycle:** start portable twice quickly; verify second instance is rejected without corrupting the DB. Close window, check Electron/backend/Chromium descendants actually exit and the root launcher terminates. If any are left, do not run an upgrade until exited. Repeat on abnormal application crash and Windows restart.
9. **Custom download paths:** choose a manual location outside Data and confirm it remains outside by user choice; restore new-profile default under Data. The builder must not delete, move, or rewrite downloaded music in either location.
10. **Drive/folder relocation:** exit the app, move to `E:\Move QBZ\...`, relaunch from root. Confirm theme, database and downloaded portable files remain. Repair manually any stored absolute settings pointing to old locations.
11. **Upgrade/reinstall:** use two different builder releases, backup Data, put new App/launcher beside existing Data. Verify installed-package updater preserves Data, old logs, and any recovery assets. Compare file hashes of Data before/after installer **before app launch**; installer must not wipe user data.
12. **Rollback:** after testing a newer version, restore both old binary tree **and** its matching Data backup. If a database migration occurred, confirm old executable does not consume new schema without restoring backup.
13. **Installer setup:** in disposable folder, run `.paf.exe`, choose install destination, confirm correct root executable and no unintended system-wide changes. Run installer a second time over test Data, verify Data untouched and obsolete application binaries replaced. Review actual NSIS logs/outcome; a static PE check is insufficient.
14. **Unexpected host writes:** for any verified persistent app-owned trace, record exact source/OS path, process, timestamp, before/after fingerprint, empty directories, symlinks/junctions and installed-profile coexistence. Only then design and validate a *narrow*, idempotent recovery adapter with conflict preservation. Generic AppData or registry sweeping is prohibited.
15. **Credentials across Windows accounts:** after backup, move the whole folder to a second test Windows account/PC. Confirm nonsecret configuration remains; expect protected tokens to require re-entry when safeStorage/DPAPI cannot decrypt them. Do not undermine encryption to force mobility.

Report results independently as **MANUAL-WINDOWS-TESTED PASS/FAIL** for launcher startup, backend/SQLite, downloads, media helpers, OS profile containment, notifications, process exit, relocation, installer behavior, upgrades, rollback, and host coexistence. No result here is pre-marked as passed.
